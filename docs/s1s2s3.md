
# S1 / S2 / S3

## S1
Header / What & Where (the short lead that states who issued the alert, what the event is, and where it applies)

Example: “[SENDING AGENCY]: A 9-1-1 outage alert is in effect for [LOCATION].”


## S2
Action(s) / Immediate instructions (what recipients should do now; the actionable steps)

Example: “If you have an emergency, contact local police, fire, or medical services at their local phone numbers.”


## S3
Warning / Additional safety note or closing (short consequence, caveat, or additional info)

Example: “If you dial 9-1-1, you may not get help.”



## Why use this 3-part canonicalization

Alerts are often structured: a lead, instructions, and a closing warning. Canonicalizing into S1/S2/S3:

Makes automated QA simpler (check S2 contains required actions),
Simplifies alignment across languages (compare S2→S2 across languages),
Enables templating and concise channel-specific rendering (SMS/IVR),
Reduces noise for modeling (train models to produce canonical segments).



## How to create canonical S1/S2/S3 pairs

Identify sentence boundaries

Use a robust sentence splitter per language (stanza for many languages, regex rules for simple cases). Split the alert into sentences (or clauses if sentences are missing).


## Rule-based mapping to S1 / S2 / S3

- **S1**: the first sentence that mentions the event type or agency or location.

    Look for keywords: publish/issued/alert/warning/alarm, agency placeholders ([SENDING AGENCY]), location placeholders.

- **S2**: the sentence(s) that instruct recipients what to do.

    Look for imperative verbs and request keywords: “call”, “evacuate”, “shelter”, “move”, “do not”, “use bottled water”, “seek shelter”, “take shelter”, “turn off”.

- **S3**: any follow-up warning or caveat — often contains “may”, “might”, “could”, or clarifying statements like “If you dial 9-1-1 you may not get help”.

    If an alert has more than three sentences, attempt to group extra sentences logically (e.g., S2 can contain multiple actions; combine them into one canonical S2 separated by semicolons).


## Canonicalization rules & placeholders


Replace variable content with placeholders and keep them identical across languages:

```python
[SENDING AGENCY], [LOCATION], [TIME], [PHONE_1], [URL], [SHELTER_NAME]
```


Normalize spacing/punctuation: trim whitespace, ensure sentence ends with a period, consistent quotations.
Prefer concise S1/S2/S3 (one sentence each) to make modeling simpler.

Examples (English)
Input alert:
"[Seattle Police & Fire] — There is a major disruption to calling 9-1-1 in Seattle. If you cannot reach Seattle 9-1-1, call 206-583-2111 or 206-625-5011, or text 911 ONLY for emergencies. If you dial 9-1-1 you may not get help."
Canonical S1/S2/S3:

```python
S1: "[SENDING AGENCY]: A 9-1-1 outage is in effect for [LOCATION]."
S2: "If you cannot reach 9-1-1, call [PHONE_1] or [PHONE_2] or text 911 only for emergencies."
S3: "If you dial 9-1-1, you may not get help."
```

## Edge cases & decisions

- Multi-clause S2: combine them into one canonical S2 with semicolons or separate bullets internally.

- Missing S3: leave canonical S3 empty (but keep S3 field present).

- Multiple actions in S2: keep order of actions semantically significant (e.g., preferred contact methods first).

- Non-standard alerts: some alerts are a single sentence; map that to S1 or S2 depending on whether it’s informational or actionable.

- Cultural/local variations: canonical text should preserve local conventions (e.g., date/time formats as placeholders).

## Annotation guidelines (for human annotators)

- Always preserve placeholders verbatim.
- Try to keep S1/S2/S3 short (≤ 30–35 words for SMS compatibility) while preserving all required instructions/entities.
- If an item contains multiple phone numbers, map them to [PHONE_1], [PHONE_2] in appearance order.
If unsure where to split, place ambiguous sentence into S2 (actions) if it contains verbs instructing behavior; otherwise S3.


A) Simple heuristic splitter that attempts S1/S2/S3 (Python, using stanza when available)
```python
 
import re
import stanza  # pip install stanza; stanza.download(lang) as needed

def canonicalize_alert_sentences(sentences, lang_hint=None):
    """
    sentences: list[str] (already split)
    returns: (s1, s2, s3) strings (empty if missing)
    Simple heuristic:
      - s1: first sentence mentioning 'alert'/'warning'/'issued' or containing placeholders
      - s2: first sentence containing action verbs (call, evacuate, shelter, boil, leave, etc.)
      - s3: any sentence that mentions consequence (may, might, could) or mentions dialing 9-1-1 warning
    """
    s1 = s2 = s3 = ""
    # lowercase for keyword checks
    low = [s.lower() for s in sentences]
    # S1 heuristics
    for i, s in enumerate(low):
        if any(k in s for k in ["alert", "warning", "issued", "in effect", "is in effect", "announced", "发布", "發佈"]):
            s1 = sentences[i].strip()
            break
    if not s1 and sentences:
        s1 = sentences[0].strip()

    # S2 heuristics (action verbs)
    action_keywords = ["call", "evacuate", "shelter", "leave", "go to", "move to", "boil", "use bottled", "contact", "text", "dial", "do not", "stay inside", "stay indoors"]
    for i, s in enumerate(low):
        if any(k in s for k in action_keywords):
            # pick the first action sentence that is not the same as s1
            if sentences[i].strip() != s1:
                s2 = sentences[i].strip()
                break
    # fallback: if no s2 and more than one sentence, pick second sentence
    if not s2 and len(sentences) >= 2:
        s2 = sentences[1].strip()

    # S3 heuristics (warnings/consequences)
    warn_keywords = ["may", "might", "could", "可能", "可能会", "may not", "may be", "may not get help", "unable"]
    for i, s in enumerate(low):
        if any(k in s for k in warn_keywords):
            if sentences[i].strip() not in (s1, s2):
                s3 = sentences[i].strip()
                break
    # final fallback: choose last sentence if non-empty and not equal to s1 or s2
    if not s3 and len(sentences) > 2:
        candidate = sentences[-1].strip()
        if candidate not in (s1, s2):
            s3 = candidate

    return s1, s2, s3
```

B) Example usage with sample:
```python
sentences = [
    "[SENDING AGENCY]: [LOCATION] 发布了 9-1-1 故障警报，当前生效中",

```

C) Entity placeholder replacement (to protect entities during training)

  
```python
import re
PHONE_RE = re.compile(r'(\+?\d[\d\-\s\(\)]{6,}\d)')
def mask_entities(text):
    phones = PHONE_RE.findall(text)
    for i, p in enumerate(phones, start=1):
        text = text.replace(p, f"[PHONE_{i}]")
    # other placeholders left as-is
    return text, phones
```

## Evaluation specifics

Entity conservation: placeholders must match exactly.
Action preservation: presence of required action keywords in canonical S2.
Semantic similarity: embeddings similarity between canonical target and model output.
Human review: at least a small panel to verify action instruction integrity.

## Annotation workflow & tooling

Create a simple annotation spreadsheet or JSONL with English alert, translations, and canonical S1/S2/S3 slots.
Annotators: bilingual reviewers for each language produce canonical S1/S2/S3.
QA check: automatic checks for placeholders and entity counts before human review.

## When to use canonical pairs vs full freeform translation

Use canonical pairs for safety-critical pipeline steps (QA, publishing templates, downstream checks).
Preserve original freeform translations too (for archival and context).
